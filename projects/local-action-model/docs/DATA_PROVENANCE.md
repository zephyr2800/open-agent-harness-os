# Data and provenance

## Bootstrap fixture

`train.generate_reference_sft` can create
`fixtures/training/action-sft-v0.jsonl` from the frozen
`fixtures/tasks/task-spec-v0.json` file. Each record contains the model input,
the complete Action IR target, and provenance fields.

This file is synthetic oracle data generated by the deterministic reference
policy. It is intended to test serialization, replay, and training plumbing.
It is not independent evidence, is not a human preference dataset, and must
not be used to claim that a trained model generalizes.

## Mid-training and preference fixtures

`train.generate_midtrain` emits `action-midtrain/v0` rows containing protocol
text, task context, and reference decisions. `train.transformers_midtrain`
implements next-token domain-adaptive training over those rows. The current
generator is deliberately synthetic and inherits the task-spec oracle warning.

`train.transformers_dpo` validates `action-preference/v0` rows and provides an
optional TRL + PEFT DPO/LoRA path. The current preference generator mutates the
same deterministic oracle decisions, so its dry-run and any resulting adapter
are plumbing artifacts until independently reviewed teacher or human data is
introduced.

## Required data records for research training

Before reporting a specialized-model result, replace or augment the bootstrap
fixture with trajectories that preserve:

- goal and constraints;
- retrieved tools and state digest;
- model decision and raw output;
- tool observation and independent verifier result;
- error category, recovery, abstention, and final outcome;
- model/checkpoint revision, token counts, latency, memory, and energy where measured;
- source, license, transformation, filtering, and split provenance.

Train/validation/held-out task and tool schemas must be split before training,
and no hidden evaluator or test answer may enter the training records.
